# Red Skill 保守发布检查表

## 调研与证据

- 已说明真实用户场景、正向触发、反向触发和可检查输出。
- 已核对至少两个相邻 Skill 或通用能力，差异不是换名字或改文案。
- 核心规则、分类、阈值和依赖有 E1-E3 证据；无直接证据的部分标为 H 并附验证方法。
- 路线 A 同时看成功与对照样本；路线 B 优先一手来源且不把搜索摘要当证据。
- 原始研究材料、竞品副本和私有语料留在发布目录之外。

## 产品

- 面向用户的 Skill 名称是清楚自然的中文，名称本身能帮助理解用途。
- 发布简介、使用说明、输入输出和错误提示默认使用中文。
- 英文仅用于技术 ID、代码、命令、API、包名、协议名或确有必要的专有名词。
- 中文展示名与 kebab-case 技术 Skill ID 已明确分离，不用英文 ID 充当发布标题。
- 用一句话说明真实用途，触发条件不会吸引无关任务。
- 输入、输出、失败条件和不处理范围明确。
- 首版只保留一个核心价值，不靠功能堆砌。

## 可移植性

- 无个人绝对路径、主机名、账号或内部项目名。
- 无未随包提供的私人 Skill、脚本、数据库或知识库依赖。
- 外部依赖可公开获得，版本清楚，有缺失时的停止或降级策略。
- 不把历史输出、状态文件、缓存、日志和备份打进包。

## 安全与隐私

- 无 token、Cookie、密码、密钥、私有 endpoint 或凭据读取逻辑。
- 无 `.env`、私钥、证书私钥、凭据文件或指向发布目录外部的符号链接。
- 敏感输入默认本地处理，不暗中上传。
- 安装依赖前说明来源和修改范围，不使用管理员权限。
- 外部写入、发布和提交动作有清晰授权边界。

## 原创与许可

- 原创工作流、第三方依赖和引用材料分开说明。
- 第三方代码保留许可证、版权和来源。
- 不打包无权公开的语料、课程、文章、图片或数据库。

## 质量

- frontmatter 至少有合法 `name`、`description`、`version`、`author`。
- description 同时说明做什么与何时使用；正文含正向和反向触发。
- `SKILL.md` 目标不超过 300 行，超过 500 行必须拆分。
- 执行步骤使用真实命令或明确自然语言，不用伪代码冒充可执行流程。
- 计算类 Skill 有黄金样例、非法输入和边界测试。
- 指令类 Skill 至少有两个代表性请求、一个误触发请求和一个失败输入的验证。
- 结构化字段和中间文件都有实际读取方，不生产零消费者指标。
- README、变更日志、设计草稿等非运行必需文件不进入 Red Skill 包。

## GitHub 与 Red Skill

- 公开仓库内容与准备发布的 Skill 内容一致。
- 推送前工作树只包含预期文件，扫描无高风险项。
- GitHub 仓库默认公开且与 Skill ID 同名。
- Red Skill CLI 只先 dry-run；最终提交另行确认。
- 原创/转载、转载来源和标签来自用户当前会话的明确答复，不从 Skill 内容或历史记录推断。
